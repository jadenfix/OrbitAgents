# Property search runtime

The dashboard sends the exact natural language query to `POST /api/query/search_pipeline` and shows only the configured service's listings, parsed criteria, counts and timings. Initial state, successful zero matches, and unavailable/malformed providers have separate messages. Old responses cannot overwrite newer searches; errors clear previous listings. A query draft is saved on this device per authenticated user. Search results and browser execution are not invented or advanced by timers.

For local development, run the real `services/auth` and `services/query` applications with their documented databases, Redis and property index. Run the gateway from the repository root (`python -m flask --app api.index run --port 8080`), setting `AUTH_SERVICE_URL` and `QUERY_SERVICE_URL` to their real service origins. Vite's `/api` proxy targets `API_GATEWAY_URL` (default `http://localhost:8080`); its `/api/query` proxy targets `QUERY_SERVICE_URL` (default `http://localhost:8001`). Remote gateway service origins require HTTPS; loopback HTTP is allowed for local development. Credentials in URLs, redirects and unknown operations are rejected. The gateway forwards auth payloads to the real auth service and never generates credentials or stores plaintext passwords.

Hosted deployment needs genuine service origins configured by the owner; this change does not supply a hosting account, live MLS index, cloud credentials or deployment authorization. Missing origins return HTTP 503. The lightweight root `requirements.txt` describes the gateway's actual imports; `api/requirements.txt` retains the optional enhanced automation dependencies. Gateway health reports its own liveness and configuration presence, not the health of the whole platform. The browser execution endpoints return explicit unavailable/not-found statuses because there is no durable executor wired to them. `/api/demo` is informational only, and the obsolete fabricated `/api/search` is HTTP 410.

List view remains usable without Mapbox. Setting `VITE_MAPBOX_TOKEN` enables the existing provider-backed map; no token displays an explicit unavailable message. Mobile starts in list view and stacks chat above results. Sign out uses the existing authentication provider.

Validation includes the original frontend suite plus regressions for actual request criteria, current response text, provider errors, malformed data and out-of-order requests; loopback gateway transport tests prove exact HTTP forwarding, no credential-bearing redirects and no simulated success. Real auth/SQLite/JWT persistence and restart are tested separately. Contract listing fixtures in browser tests are explicitly test data; they do not verify live MLS ingestion or an OpenSearch deployment.

Run `python -m pytest api/tests/test_gateway.py api/tests/test_query_failure.py`, `python scripts/check_auth_http.py`, and `python scripts/check_product_http.py` after installing the root gateway/auth dependencies and `npm ci` plus `npx playwright install chromium` in `frontend`. The browser harness starts isolated temporary SQLite auth, gateway and Vite processes, exercises desktop and mobile, writes evidence under `artifacts/product-browser`, and terminates them. `ORBIT_CHROME_PATH` can select an already installed Chrome binary. The product workflow runs both API boundaries and browser/auth restart proofs without cloud credentials.
